## 接下来按什么顺序改

1. **P0：修评分契约。**隐藏检查不能要求题面没约定的参数或 JSON 结构；还要补上“评分放过错误”的故障边界。
2. **P0：消除收尾循环。**验收清单、工具验证与暂停状态一致，避免已完成实现却不断自检、到 32 步仍不能交付。
3. **P1：降低重复上下文成本。**先减少重复读、工具历史重放和无收益压缩，再考虑更换召回算法。
4. **P1：补副作用失败后的恢复验证。**两个文件依次替换不等于一次事务；避免重试重复扣库存。
5. **P1：补齐字段语义验收。**免税不免基础费用；版本状态正确也不能漏验提案 ID 列表。
6. **P2：扩展安全与未见覆盖。**增加 shell 瞬时副作用、链接竞争、授权撤回，以及新的封存任务族。

每项的证据、具体改法和验收条件见 [主要修改方向（按优先级）](主要修改方向.md)。

**版本要分清：**这 20 题使用之前冻结的代码。主代码随后已做的验收协议、真实前端状态和重复上下文修复，正在另一批三道前端原题上复测；不能把这些改动当作本轮 20 题已经验证改善。
