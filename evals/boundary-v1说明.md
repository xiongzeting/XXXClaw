## 本轮范围

- 15 道新题：开发、保留、测试三个预分层各 5 道，每层各覆盖召回、压缩、工具、安全、总体交付一种能力。
- 5 道旧题：从路径误报纠正后的历史记录筛选，五个评分维度中至少两个未通过才加入。保留原分层来源，执行时单列为已曝光回归。
- 统一使用 `gpt-5.6-luna`，每题一次，两路并行。新题、旧题分别统计，不用旧题成绩充当新题成绩。
- 先冻结参考实现、错误样例、题目、输入与 Agent 源码，再执行整批。整批结束后才检查模型成绩。

## 这次新增的难点

| 能力 | 重点 |
|---|---|
| 记忆召回 | 当前工作区不放事实；隔离会话，只开放记忆工具，阻止直接读旧会话文件绕过召回；覆盖关系组合、迟到更正、来源冲突与明确未知 |
| 上下文压缩 | 多轮修订后撤回旧补丁、撤销局部例外、区分正式版本与被拒提案；同时检查答案和压缩/归档机制 |
| 工具调用 | 不确定提交结果下的幂等恢复、批量操作的原子性、多个模块和 CLI 之间的契约 |
| 安全执行 | 不可信工具输出伪装授权、只读到交付再撤回的阶段约束、嵌套与循环/悬空链接 |
| 总体交付 | 真实执行多模块程序与 CLI，检查异常输入、重复数据、退出码及旧输出保留，不只看文件存在 |

## 判分校准与边界

每道新题的主要答案检查都先运行合格参考行为及至少两种错误行为；另对过程、成本、路径与运行状态检查做正反例校准。代码题参考实现和错误实现通过实际 Windows + Docker 执行。参考实现、预期答案和隐藏检查不进入模型工作区。

正反例通过只证明这些已知样例的判分符合预期，不证明 oracle 已覆盖所有错误。公共 smoke 仅供开发参考，最终由隐藏检查判断契约。压缩次数通过不等于所有记忆都保留；次数不足也不能直接说记忆丢失。

安全证据须按实际覆盖解释：`tool_write_paths` 审计成功的 edit/write 路径，可发现这些工具的写后删除；工作区差异检查最终残留。二者不能完整捕获任意 bash 的瞬时改写。阶段题的 API 日志只证明规定接口的调用，不是不可伪造的系统级审计。链接题检查生成程序的行为，不自动代表整个 Runtime 的所有越界通路都安全。

## 网络与曝光口径

VPN 等导致的连接中断只对断点请求有限重试，保留此前工具结果与预算。恢复成功后看实际交付，原错误、恢复链和累计成本另存；不因一次网络失败全量重跑或直接判断能力差。

本轮只有一次执行。预分层是数据管理安排，不等于已建立充足的独立盲测集。成绩被阅读并用于后续修改后，这些题均属于已曝光评测材料；失败题导出为开发回归，未来最终报告仍需封存的新任务族。
