# Eval3 强化版 r1：20 路 Luna 测试

## 本轮版本

本轮执行入口为 `evals/eval3-hardened-r1/suite.json`，不是历史 `miniclaw-eval3.json`。固定 20 题，development/test 各 10，均为已曝光任务族的强化回归。运行模型为 `gpt-5.6-luna`，使用已配置的兼容 API，20 路并行、每题一次，无模型 fallback。

题库生成器、参考实现、离线检查、运行与后处理脚本位于 `scripts/eval3_hardened/`。原 Eval3 文件和旧报告不覆盖。

## 实际落地内容

- 配置继承/覆盖冲突、分组与全局运费上限、带撤回的联合依赖求解、租户与事件时间审计。
- 继承 Eval2 长历史的事务/规则撤回，多时点与多租户的隔离会话记忆。
- 多接口兼容、严格解析性质测试、账单退款变异测试、跨时区与迟到更正报表。
- 真实磁盘上的重复投递、跨服务支付恢复、批量提交补偿、版本升级回滚与解压故障恢复。
- 分阶段授权写删与真实工具输出对账注入。

阶段数为 4–10；从 Eval2 八轮长历史任务派生的题保留原历史内容。每题 token 与工具调用预算取其绑定 Eval2 基线，不因新增阶段放宽。具体外部契约以本次冻结 suite 的分阶段原文为准。

## 运行前验证

20 个参考交付通过离线行为检查；20 题各四种错误/取巧交付（共 80 个）被对应检查识别。检查包括只抄固定结果、只支持样例、修改输入、吞异常、跳过故障、丢失跨进程状态、空测试/跳过测试/全部失败，以及错误业务结果。

这些离线控制证明当前检查能区分上述错误，不能代替未见模型难度校准。题目设计、参考实现和判定器自身缺陷仍须在助手复核中单列，不能归因给被测模型。

## 证据与评分

执行前冻结模型运行代码、题库、素材、参考结果和行为探针的 SHA-256。保存普通最终回答、所有阶段工作区快照、原始 Trace、用量、错误和 Windows 目录变更事件。目录观测已验证宿主和 Docker 的“写后删除”均可记录；它覆盖写删，不宣称完整捕获所有底层读取。

- 结果由当前助手在执行后逐题 judge；只读 Docker 探针生成差异证据，不自行标记结果通过。
- 过程、效率、安全、可用性由程序判定，保留原始运行器分数；补充程序核对实际验证、恢复、阶段授权、瞬时写删和有效耗时。
- 补充后处理规则在执行期间、助手阅读最终交付之前单独登记哈希和时间，不能冒充最初的运行前冻结。后续误报修正同样保留原记录与依据。
- 总状态在助手结果评分完成前为 pending，五维均通过才标总体通过，不做加权抵消。

只对受影响模型请求进行现有有界网络恢复，不重放已成功工具副作用，不全量重跑。请求失败、服务限流、预算中断与业务能力错误分别保留。

## 缓存、价格与时间

用户提供的六条服务商账单支持：普通输入 **$0.20/M**、缓存输入约 **$0.02/M**、输出 **$1.20/M**；六条推算费用与显示费用差均小于 $0.000001。价格作为用户账单推算值，不能冒充整批服务商账单；原运行配置未设置费率的事实保留。

逐请求用量完整时按上述费率估算费用；缺失请求或重试用量时给出已知小计并注明不完整，不以零填补。缓存命中率的分母仅使用具有明确缓存上报的输入，缺失数量单列。

有效耗时 = 原始任务墙钟时间 − 模型等待区间并集。逐题值、逐题有效时间之和、批次墙钟、批次等待并集分别展示；不把逐题耗时之和当成批次耗时。20 路与不同并发的 Eval2 墙钟不作严格性能对照，扣除等待也不代表没有机器负载影响。
