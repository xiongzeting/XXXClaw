# MiniClaw 分层项目指令自动加载

## 1. 这次实现解决什么问题

编码 Agent 不能只理解代码，还必须先理解“这个仓库要求它怎样改代码”。测试命令、目录边界、命名方式、生成文件规则、禁止触碰的区域，通常都写在 `AGENTS.md` 一类文件中。如果模型没有收到这些规则，即使代码逻辑正确，也可能违反仓库规范。

MiniClaw 现在会按下面的优先级自动解析指令：

```text
用户全局指令
    ↓
有效工作区根目录指令
    ↓
已激活目标的祖先目录指令
    ↓
距离目标文件最近的局部指令
    ↓
本次用户请求
```

前四层进入 System Prompt；本次用户请求仍保持独立的 `user` 消息。这样不会把“用户这次要做什么”和“仓库长期要求怎样做”混成一段不可追踪文本。

## 2. 与 pi-mono 的关系

pi-mono 的 `loadProjectContextFiles()` 会：

- 从 `~/.pi/agent` 读取用户全局上下文；
- 从当前目录向文件系统根目录逐层寻找上下文文件；
- 每个目录按 `AGENTS.md`、`AGENTS.MD`、`CLAUDE.md`、`CLAUDE.MD` 顺序选择第一个存在的文件；
- 将找到的文件按“全局到局部”的顺序拼入 System Prompt；
- 支持重新加载资源。

MiniClaw 保留了文件名顺序和由低到高的拼接方式，但使用自己的 `~/.miniclaw` 作为默认全局目录，并做了适合当前 Python 架构的增强：

- 不扫描工作区外的任意父目录，项目规则被严格限制在 Runtime 的有效工作区中；
- 按工具目标逐步激活嵌套规则，避免启动时把整个大型仓库的所有局部文件塞入上下文；
- 首次写入前若发现模型尚未看到的局部规则，会先暂停写入并刷新 Prompt；
- 每个来源都带有作用域、层级、Hash、Token 和状态记录；
- 指令文件变化后自动失效，不要求重启会话或手动 `/reload`；
- Direct 与 Snapshot 模式都从真正会被工具修改的 `runtime.host_workspace` 加载。

## 3. 模块结构

```text
src/MiniClaw/coding_agent/instructions/
├── config.py   环境变量、默认预算、全局目录和候选文件名
├── model.py    InstructionSource 与 InstructionResolution 数据结构
├── loader.py   发现、作用域计算、缓存、预算分配和 Prompt 渲染
└── __init__.py 对外导出
```

### `InstructionConfig`

配置项包括：

- `enabled`：是否启用自动项目指令；
- `token_budget`：一次模型请求最多分配给项目指令的估算 Token；
- `global_directories`：用户全局指令目录；
- `filenames`：每个目录的候选文件名及优先顺序。

默认全局目录为：

```text
~/.miniclaw
```

设置 `MINICLAW_AGENT_DIRS` 后会完全使用用户提供的目录列表。

### `InstructionSource`

每个发现的指令文件会保存：

- 真实路径与用于显示的工作区相对路径；
- `global / workspace / local` 层级；
- 生效目录，也就是 scope；
- 相对工作区的深度；
- SHA-256；
- `mtime_ns` 和文件大小；
- 原始估算 Token 与实际注入 Token；
- `included / truncated / omitted` 状态；
- 原始内容和本次真正注入的内容。

完整内容只用于构造当前模型请求，不会重复写入 `instructions.injected` Trace 事件。

### `InstructionResolution`

一次解析结果包含最终 Prompt 片段、全部来源、预算、实际使用量、当前激活的目标路径和整体 Digest。Digest 用来判断两次模型请求之间是否真的发生了指令变化，避免 Trace 重复记录相同快照。

## 4. 发现与作用域规则

每次用户请求开始时，Loader 会重置目标集合，并激活有效工作区根目录。随后文件工具会继续激活路径：

| 工具 | 激活方式 | 是否可能暂停本次调用 |
|---|---|---|
| `read` | 激活被读取文件及其祖先目录 | 否，下一模型轮刷新 |
| `grep` | 激活显式搜索目录，并在完成后激活匹配文件 | 否，下一模型轮刷新 |
| `write` | 激活目标文件的父目录链 | 是，发现未注入规则时先暂停 |
| `edit` | 激活目标文件的父目录链 | 是，发现未注入规则时先暂停 |
| `bash` | 当前实现只以工作区根为执行 cwd，不推测命令内部会访问哪些文件 | 否 |

对 `src/api/client.py`，只有下面这些项目指令可能对它生效：

```text
<workspace>/AGENTS.md
<workspace>/src/AGENTS.md
<workspace>/src/api/AGENTS.md
```

兄弟目录 `src/web/AGENTS.md` 不会被当成 `src/api/client.py` 的规则。若两个分支都在一次运行中被访问，它们可以同时出现在 Prompt 中，但每段都会明确标记 `Applies to`，模型只能在对应 scope 内应用。

## 5. 层级覆盖

最终 Prompt 明确告诉模型：

```text
user-global < workspace root < deeper local scope < current user request
```

覆盖是带作用域的。例如：

- 根目录要求 Python 使用双引号；
- `legacy/AGENTS.md` 要求保持该目录原有单引号；
- 修改 `legacy/parser.py` 时局部规则优先；
- 修改 `src/new.py` 时 `legacy` 规则完全不适用；
- 用户本次明确要求进行一个与项目规则冲突但安全的变更时，本次请求优先。

系统安全约束、工作区边界和审批策略不属于可被项目文件覆盖的用户级规则。

## 6. Token 预算

默认预算为 12,000 个估算 Token：

```text
MINICLAW_INSTRUCTIONS_TOKEN_BUDGET=12000
```

MiniClaw 使用与工作上下文相同量级的轻量估算，即约四个字符一个 Token。预算分配不是简单从文件列表开头截断，而是：

1. 先按优先级从最局部来源向全局来源分配空间；
2. 最局部文件能完整放入时完整保留；
3. 单个高优先级文件过大时保留头部和尾部，并插入截断标记；
4. 空间不足的低优先级来源标记为 `omitted`；
5. 最终展示仍按“全局到局部”排列，便于模型理解覆盖关系。

因此预算紧张时，目标文件附近的规则不会因为一个很长的全局说明而被挤掉。所有截断和省略都会进入 Trace，不会静默发生。

## 7. 缓存与自动失效

Loader 为读取过的文件保存缓存，缓存签名包含：

```text
绝对路径 + mtime_ns + 文件大小
```

签名变化时会重新读取内容并计算 SHA-256。下一次模型请求或写入前检查会得到新的 Resolution Digest。这样修改 `AGENTS.md` 后不需要重启 MiniClaw；如果文件恰好在模型已经决定写入之后发生变化，写入前保护也会拦住旧指令下产生的修改。

## 8. 为什么 write/edit 要先暂停一次

局部规则只有在模型给出目标路径后才可能被发现。若模型第一轮直接调用：

```text
write(path="src/api/client.py", ...)
```

而 `src/api/AGENTS.md` 尚未注入，直接执行会造成真实副作用。现在流程是：

```text
模型提出 write/edit
→ 指令 Preflight 解析目标路径
→ 发现新的或发生变化的适用来源
→ 返回 instructions_refresh_required
→ 不进入审批，不执行文件修改
→ 下一轮 AgentLoop 动态重建 System Prompt
→ 模型阅读局部规则后重新决定并重试
```

阻止结果会明确写明 `No file was modified`，并在 ToolResult details 中包含目标路径、来源列表和 Resolution Digest。第二次调用若规则未再变化，就可以正常进入危险操作审批和真实工具执行。

统一 Trace 将这次预检结果记为 `tool.call status=blocked`，而不是普通 `error`，因此它不会污染工具失败率或被错误聚类为产品故障。

## 9. AgentLoop 为什么只增加 Provider 回调

`AgentLoop` 仍然是通用模型/工具循环。它不知道 `AGENTS.md`、目录层级或写入保护，只新增了一个同步的 `system_prompt_provider`：每次准备模型请求时取最新 System Prompt。

具体策略全部留在 `CodingAssistant` 和 `instructions` 模块中：

```text
AgentLoop._request_messages()
→ CodingAssistant._provide_system_prompt()
→ ProjectInstructionLoader.resolve()
→ 组合基础 Prompt、项目指令、Goal 和记忆上下文
```

这样未来其他产品可以继续使用静态 `system_prompt`，也可以提供自己的动态 Prompt，而不用继承编码项目规则。

## 10. Runtime 与会话隔离

加载根目录固定使用：

```python
runtime.host_workspace
```

- Direct：它就是原始项目目录；
- Snapshot：它是当前会话自己的 `.aster/.../sandbox/workspace`；
- Docker：文件工具和指令 Loader 仍在宿主 Python 进程中观察同一个有效工作区，Bash 在容器里看到 `/workspace` 映射。

飞书每个 conversation 都创建独立 `CodingAssistant`，所以激活路径、缓存快照和本轮已注入来源不会跨会话共享。

## 11. Trace

每次实际注入发生变化时记录：

```json
{
  "type": "instructions.injected",
  "data": {
    "reason": "dynamic_refresh",
    "budget_tokens": 12000,
    "used_tokens": 4300,
    "target_paths": [".", "src/api/client.py"],
    "digest": "...",
    "sources": [
      {
        "path": "src/api/AGENTS.md",
        "scope": "src/api",
        "level": "local",
        "depth": 2,
        "sha256": "...",
        "mtime_ns": 0,
        "size_bytes": 2048,
        "estimated_tokens": 520,
        "injected_tokens": 550,
        "status": "included"
      }
    ]
  }
}
```

`run.started` 同时记录本轮初始指令 Digest、预算、使用量和来源数量。模型边界 Trace 仍保存最终经过统一脱敏的请求上下文，因此离线 Replay 可以重放当时模型真正看到的 System Prompt。

## 12. 配置

```text
MINICLAW_INSTRUCTIONS_ENABLED=true
MINICLAW_INSTRUCTIONS_TOKEN_BUDGET=12000
MINICLAW_AGENT_DIRS=
```

`MINICLAW_AGENT_DIRS` 是按操作系统路径分隔符连接的目录列表。Windows 使用分号，Linux/macOS 使用冒号。设置后不再自动添加 `~/.miniclaw`。

CLI 启动时会显示发现的来源、状态和预算使用量。飞书不额外向聊天发送这些内部信息，但完整元数据会进入对应会话的 Trace。

## 13. 测试覆盖

新增测试覆盖：

- 全局、根目录、嵌套目录的顺序和 scope；
- `AGENTS.md`、`AGENTS.MD`、`CLAUDE.md` 的候选顺序；
- 工作区外路径拒绝；
- 预算不足时局部规则优先；
- 文件变化后的缓存自动失效；
- `read` 后下一轮动态注入；
- 首次 `write` 在局部规则尚未注入时不修改文件；
- 第二次写入在刷新后正常执行；
- Trace 的来源、Hash、Token 和状态；
- Snapshot 从有效任务工作区加载；
- 原有完整测试回归。
