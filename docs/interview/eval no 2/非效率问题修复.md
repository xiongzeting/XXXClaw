## P0：验收没过，不能显示任务完成

**原来：**验证脚本只要给出 `passed=true` 和一段证据文字，就可能满足一条清单。清单没有独立复核实际值与预期值；一次错误格式的复核还可能清掉其他有效证明，增加重复验证。收尾也需要一道最终状态兜底。

**修改：**复核先作废本次点名的验收项，保留未变化的其他证明；格式错误、非零退出、漏项继续阻止完成。需要重新验证时保存明确下一步。最终收尾再次检查，未通过则持久化暂停和可恢复上下文，运行状态及 Trace 都记暂停，并单独记录 `verification_incomplete` 原因。对外复用现有暂停通路，仍保留 32 步上限。

**已验证：**错误复核不能让旧的失败证明重新变成有效；无关证明可以保留；未验收任务不会被最终运行记录标成成功。测试覆盖 Assistant、状态存储和 Trace；本轮没有打开前端重新点击验收。

## P1：不只看“总数对了”，逐字段检查真实值

**依据：**阶梯发票把免税算成免费；依赖锁题主版本正确，却把需要输出的提案 ID 换成了约束表达式。前者需要拆开验证基础费用、税、合计，后者需要验证 ID 列表的成员和顺序。不能把这些错误直接解释成记忆丢失。

**修改：**验收项支持 `data` 类型和必查字段编号，验证脚本上报实际值、预期值及比较方式，由 Runtime 重新计算是否通过。支持严格类型、对象字段、数组顺序比较；无序比较仍检查重复数量。漏字段、重复编号、非有限数或伪造 `passed=true` 不能盖过失败的比较。

实际值可从工作区 JSON 文件读取，支持具体字段路径；文件读取复用 Runtime 的工作区和敏感路径保护。记录文件 SHA-256，内容改变后证明失效。字段可绑定最终 JSON 回复：已验证的 ID 列表不能在最后一句又被改掉，错误候选回复会被拦住，再在原步数预算内修正。完整比较值留在验收记录中，不反复注入上下文。

**已验证：**真实 Host 命令读取输入并推导金额与 ID，Runtime 读取输出文件逐字段比较；脚本化模型先给漏成员的最终 JSON、再给正确 JSON，前者未作为助手回复发出，后者正常完成。共执行一次检查点工具和一次验证命令，没有重放工具。相对路径、Docker 路径及合法宿主路径指向同一输出；越界和受保护文件被拒绝。

**范围：**强字段验收须显式登记 `kind=data`（或 `recovery`）及 `check_ids`；旧 `behavior` 协议保持兼容。预期值仍可能由模型写的程序算错，内联实际值也可能填错。这里增强的是比较、覆盖和交付一致性，不能代替外部可信答案。没有显式绑定 `final_pointer` 的普通文本回复不受 JSON 字段约束。

## P1：把“写一半出错、再试一次”变成可复用检查

**依据：**原子预留的追加诊断中，库存第一次从 10 扣到 9，记录文件提交失败；相同请求重试后变成 8。两个文件分别原子替换，并不等于整个业务原子完成。

**修改：**新增通用提交故障探针 `probe_recovery`。先正常执行以识别 `os.replace` / `os.rename` 提交点，然后在每个点的执行前、执行后分别注入异常。每次重建临时状态，检查失败后是否全旧或全新，以及同一业务请求重试后的状态是否等于只成功一次；另测成功后响应丢失的重复请求。提交点默认最多 8 个，不支持的提交机制返回未覆盖，不拿它当作已通过。

任务验收增加 `recovery` 类型，要求比较项和提交前、提交中、响应丢失、重试四类场景记录。

**已验证：**同一套探针对两个文件依次替换的坏实现判失败，对本测试中带回滚的实现判通过；覆盖两个提交点的四个异常边界及成功后的重复请求。重试本身抛异常会返回结构化失败。

**范围：**四类场景记录是验证程序的声明，不是 Runtime 自动证明注入真的发生。新增探针目前是供独立测试复用的工具，没有接入正在运行的冻结版 oracle，也不会自动让模型生成的业务代码获得事务能力。探针应在隔离测试进程使用，不支持同进程并行，不模拟断电持久性、并发竞争或数据库提交；合法的其他提交机制需要对应适配器。生产业务仍需选择合适事务或日志恢复方案，独立 Eval 负责核验。
