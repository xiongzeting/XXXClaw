# MiniClaw 长期记忆混合检索与写入冲突

## 1. 检索目标

长期记忆检索需要同时解决两个问题：

- 精确项目名、路径、错误码和配置项必须稳定命中；
- 用户表达与记忆文本不完全一致时，也要有辅助召回能力。

因此 MiniClaw 不让向量分数单独决定结果，而是采用：

```text
BM25 主召回 ─────┐
                 ├─ 加权 RRF ─→ 候选集合 ─→ rerank ─→ Prompt Memory
向量辅助召回 ────┘
```

## 2. BM25 主检索

BM25 权重默认为 `0.78`。它主要负责：

- 文件名、函数名、模型名和错误码；
- 中文项目术语；
- 多次出现的关键词；
- 稀有词比常见词更高的 IDF 权重。

分词同时支持英文单词、中文单字和中文二元词组。这样不依赖外部分词服务，也能处理“数据库连接池”之类的中文查询。

## 3. 向量辅助检索

向量权重默认为 `0.22`，明确低于 BM25。

当前默认编码器是本地 signed feature hashing：

- 384 维稠密向量；
- 使用词 Token 和字符三元组；
- L2 归一化后计算 cosine similarity；
- 不调用额外模型，不产生 Embedding API 费用；
- 对中文、代码符号、拼写变化和局部相似表达提供辅助召回。

编码器由独立接口边界封装，后续可以替换成远程语义 Embedding，而不改变 BM25、RRF 和 rerank 流程。

## 4. 加权 RRF

BM25 和向量结果使用 Reciprocal Rank Fusion：

```text
score = 0.78 / (60 + bm25_rank)
      + 0.22 / (60 + vector_rank)
```

使用排名而不是直接相加原始分数，是因为 BM25 和 cosine 的数值范围完全不同。RRF 避免为两套分数做脆弱的人工归一化。

BM25 权重更高，因此精确词命中仍是主导；向量候选可以进入候选池，但不会轻易压过强 BM25 结果。

## 5. Rerank

RRF 后对最多 24 个候选做第二阶段确定性 rerank，特征包括：

- 归一化 RRF 分数：70%；
- 查询词覆盖率：18%；
- 记忆主题字段匹配：7%；
- 完整短语匹配：4%；
- preference 类别轻微加成：1%。

最终最多向 System Prompt 注入 5 条记忆。Prompt 中带稳定的 `mem_<hash>` record ID，便于后续检查和冲突处理。

## 6. 写入冲突

写入前会提取记忆主题。支持的主题形式包括：

```text
language: Python
项目数据库使用 PostgreSQL
runtime is Docker
```

如果同一类别、同一主题已经存在不同值，默认不覆盖，而是写入：

```text
.aster/memory/MEMORY.conflicts.jsonl
```

冲突记录包含：

- conflict ID；
- category 和 subject；
- existing 与 proposed 内容；
- pending/resolved 状态；
- 创建、解决时间和最终 resolution。

## 7. 冲突策略

`memory remember` 支持四种 `conflictPolicy`：

| 策略 | 行为 |
| --- | --- |
| `reject` | 默认，创建 pending conflict 并要求用户决定 |
| `keep_existing` | 保留旧值，不写新值 |
| `replace` | 用新值替换旧值 |
| `keep_both` | 用户明确确认后并存 |

默认 reject 返回结构化数据，包含 conflict ID 和允许的解决动作。

随后使用：

```json
{
  "action": "conflict_resolve",
  "conflictId": "conflict_xxx",
  "resolution": "replace"
}
```

也可以通过 `conflict_list` 查看 pending、resolved 或全部冲突。

系统提示词明确要求模型不能自行猜测解决方案，必须先向用户说明 existing/proposed，再按用户选择解决。

## 8. 并发写保护

飞书不同线程可能同时写同一个 `MEMORY.md`。仅使用临时文件原子替换仍可能出现：

```text
线程 A 读取旧版本
线程 B 读取旧版本
A 写入
B 写入并覆盖 A
```

MiniClaw 增加跨线程、跨进程 lock file：

1. 使用独占创建获得写锁；
2. 锁内重新读取最新 Memory；
3. 做重复与主题冲突检查；
4. 写入唯一临时文件；
5. 原子 replace；
6. 释放锁。

锁等待默认 3 秒，30 秒以上的遗留锁视为崩溃残留并安全清理。

## 9. Memory 工具动作

新增动作：

- `search`：返回最终分数、RRF、BM25/向量分数和各自排名；
- `conflict_list`：列出冲突；
- `conflict_resolve`：显式解决冲突。

原有 `read / remember / replace / forget` 保持兼容。

## 10. 测试覆盖

专项测试覆盖：

- BM25 权重大于向量权重；
- BM25 和向量共同命中的结果稳定第一；
- BM25 未命中时向量可以辅助召回；
- 混合结果进入 Prompt；
- 冲突跨重启持久化；
- replace、keep_existing、keep_both；
- 两个并发写入不会互相覆盖。
