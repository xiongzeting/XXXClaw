# 7. Trace 与 Eval 数据闭环

## 1. 目标

这次改造不是简单地再加一个日志文件，而是建立下面的数据闭环：

```text
真实 CLI / 飞书会话
        ↓
统一 trace.jsonl
        ↓
失败轨迹 → Eval Case
        ↓
切换模型 / Prompt / Tool 配置进行边界重放
        ↓
eval-results.jsonl
        ↓
失败聚类 + 回归告警 + 质量/成本 Dashboard
        ↓
修复后的新真实轨迹继续进入下一轮
```

实现参考了 pi-mono 的 Trace 类型、旧数据迁移和 Dashboard 思路，但没有照抄它的 TypeScript 结构。MiniClaw 的核心特点是 Python、Provider-neutral `ModelClient`、自动 Memory Compaction 和 Goal 外层监督，因此 Trace 选择围绕这些现有边界实现。

## 2. 为什么放在 ModelClient 外层

如果只在 `AgentLoop` 里记录模型请求，会漏掉两类重要调用：

- `GoalJudge` 的独立完成审查；
- Working Context 硬压缩时的模型摘要。

因此 MiniClaw 使用：

```text
CodingAssistant
  ↓
TracingModelClient
  ↓
OpenAICompatibleClient
```

`TracingModelClient` 包装当前模型客户端，所有通过 MiniClaw LLM 层发出的请求都会进入同一 Trace。每个 `ModelRequest.metadata.purpose` 标记用途：

```text
agent        普通 Agent 推理
goal_judge   Goal 完成 Judge
compaction   上下文压缩摘要
trace_replay 离线轨迹边界重放
```

工具、Goal 和 Compaction 结果由 `CodingAssistant` 关联到当前 run。通用 `AgentLoop` 仍然不知道 Trace 文件、飞书会话目录或 Dashboard。

## 3. 文件与身份模型

每个 Session 使用一个追加式文件：

```text
普通 CLI：.aster/trace.jsonl
飞书：.aster/feishu/sessions/<session-key>/trace.jsonl
```

三个 ID 的含义：

| ID | 含义 |
| --- | --- |
| `trace_id` | 一个会话的稳定标识，由 channel + conversation 哈希得到 |
| `run_id` | 一次 `AgentLoop.run`，Goal 的每个 attempt 都有独立 run |
| `event_id` | 一条 Trace 事件的 UUID |

Goal 外层监督可能产生：

```text
同一个 trace_id
  ├─ run_id A：attempt 1，自然停答但未验证
  ├─ run_id B：attempt 2，验证失败
  └─ run_id C：attempt 3，验证通过并 goal_complete
```

这样既能看完整会话，又能独立比较每次 attempt 的模型、成本和延迟。

## 4. 统一事件 Schema

每行结构：

```json
{
  "schema_version": 1,
  "trace_id": "...",
  "event_id": "...",
  "type": "model.request",
  "timestamp": "2026-09-01T...Z",
  "channel_id": "feishu",
  "conversation_id": "...",
  "run_id": "...",
  "parent_event_id": null,
  "data": {}
}
```

当前事件：

| 事件 | 保存内容 |
| --- | --- |
| `run.started` | 用户请求、模型、Prompt Hash、Tool 配置 Hash、Goal 起始状态 |
| `model.request` | 用途、模型、完整脱敏上下文、输出、Token、估算成本、延迟、错误 |
| `tool.call` | Tool 名称、参数、结果或错误、开始/完成时间、耗时 |
| `approval.decision` | 风险、原因、预览、审批决定 |
| `goal.snapshot` | run 开始和结束时的持久化 Goal 状态 |
| `compaction.started` | 触发前 Token 和软/硬阈值 |
| `compaction.completed` | 策略、压缩前后 Token、节省量、artifact 信息 |
| `compaction.aborted` | 软触发无法安全达到目标时的延迟压缩 |
| `compaction.failed` | 压缩过程真实异常 |
| `run.completed` | 最终状态、Stop Reason、总 Token/成本/延迟、过程统计、最终 Goal |

项目目前还没有强制审批中间件，因此 `approval.decision` 的 Schema、Recorder API 和 Dashboard 已经接好；将来接入审批策略时调用 `CodingAssistant.record_approval(...)`，不需要再更改 Trace 格式。

## 5. Token 与成本

Token 直接使用 Provider 返回的：

```text
input_tokens
output_tokens
cached_tokens
total_tokens
```

成本只在配置了价格时估算：

```dotenv
MINICLAW_PRICE_INPUT_PER_MILLION=0
MINICLAW_PRICE_OUTPUT_PER_MILLION=0
MINICLAW_PRICE_CACHED_INPUT_PER_MILLION=0
```

公式：

```text
uncached input × input price
+ cached input × cached price
+ output × output price
────────────────────────────
          1,000,000
```

如果第三方兼容接口没有公开准确价格，默认保持 0。Dashboard 仍统计真实 Token，但不会编造美元成本。更换模型重放时使用重放模型自己的价格配置重新计算。

## 6. 脱敏与数据体积

Trace 为了能够重放，会保存 system prompt、消息和工具定义，因此它比普通指标日志敏感。写入前统一处理：

- `api_key / authorization / password / secret / token / cookie` 等字段按键名脱敏；
- `sk-...`、Bearer Token 和环境变量形式的 Key 自动替换；
- 二进制或超长图片 data 不写入正文；
- 单个字符串最多 200k 字符；
- 循环对象标记为 `[CIRCULAR]`；
- 非有限浮点数归零，确保 JSON 始终可解析；
- Trace 写入失败不会中断 Agent 主任务。

注意：普通源代码、用户 Prompt 和命令输出不是 Secret，会为了可重放性进入 Trace。`.aster/` 已在 `.gitignore` 中，不应提交到代码仓库，也不应把生产 Trace 公开分享。

## 7. 从旧 tool-calls.jsonl 升级

迁移命令递归寻找 `tool-calls.jsonl` 和 `model-requests.jsonl`：

```powershell
$env:PYTHONPATH = "D:\MIniClaw\src"
python -m MiniClaw.trace.cli migrate D:\old-trace-root
```

它会在每个旧 Session 旁创建 `trace.jsonl`，映射：

```text
tool-call       → tool.call
approval        → approval.decision
model metrics   → model.request
旧 Session 汇总 → run.started / run.completed
```

如果目录已经存在 `trace.jsonl`，默认跳过，避免重复迁移。旧数据通常没有完整模型输出或可重放上下文，因此迁移后的模型边界可能只能用于指标和失败分析；新版本生成的 Trace 才是完整可重放格式。

## 8. 从真实失败生成 Eval Case

```powershell
python -m MiniClaw.trace.cli eval-case `
  D:\MIniClaw\.aster\feishu\sessions\<session-key> `
  --out D:\MIniClaw\evals\trace-regression.json
```

默认选择该 Session 最近的失败 run，也可以指定：

```text
--run-id <run-id>
```

Eval Case 包含：

- 原始用户请求；
- Trace/Run 来源；
- 失败签名和错误摘要；
- 当时的模型、Prompt Hash、Tool Hash；
- Goal 状态；
- 每个模型边界的脱敏 Context 和原输出；
- “不再出现旧失败”的回归期望。

生成文件是可移植 JSON，而不是只保存一个指向生产 Session 的路径。后续可以补充工作区 fixture、文件断言和真实验证命令，把“模型决策回归”提升为“完整任务回归”。

## 9. 模型边界重放

重放命令：

```powershell
python -m MiniClaw.trace.cli replay `
  D:\session `
  --env-file C:\path\to\pi-mono\.env `
  --model gpt-5.6-luna `
  --prompt D:\variants\system-prompt.txt `
  --tools D:\variants\tools.json `
  --case D:\evals\trace-regression.json `
  --out D:\reports\replay.json
```

Tool 配置格式：

```json
{
  "enabled": ["read", "bash", "edit", "write", "grep"],
  "disabled": ["memory"],
  "overrides": {
    "bash": {
      "description": "新的工具描述",
      "parameters": {
        "type": "object",
        "properties": {"command": {"type": "string"}},
        "required": ["command"]
      }
    }
  }
}
```

每个记录的模型请求作为独立边界重放：

```text
记录的精确 Context
  + 新 ModelProfile
  + 可选新 System Prompt
  + 可选 Tool enable/disable/description/schema
        ↓
新模型输出
        ↓
比较 Stop Reason、Tool Call 顺序、文本 Hash、Token、成本、延迟
```

### 为什么不执行工具

生产轨迹可能包含写文件、Shell、删除或网络行为。离线对比如果自动重放这些操作，会污染当前工作区，甚至产生破坏性副作用。因此默认重放严格禁止真实 Tool execution。

这个模式非常适合：

- 对比两个模型是否选择相同工具；
- 测试 System Prompt 改动是否减少错误；
- 测试禁用某工具后的决策变化；
- 比较 Token、成本和模型延迟。

它不能单独证明代码真的修好。完整正确性仍需隔离工作区、fixture 和真实 verification；这是下一层 Eval Harness，而不是让 Trace Replay 偷偷执行生产命令。

如果传入 `--case`，重放结果还会追加到 `eval-results.jsonl`。当前结果明确标记：

```text
confidence = model-boundary-only
```

避免把“模型边界没有报错”误称为“完整任务通过”。

## 10. 失败聚类

聚类使用确定性签名，不额外调用模型，成本为零且便于回归比较。优先级：

```text
model:<错误码或 stop reason>
tool:<tool name>:<错误码或归一化首行>
goal:<失败原因>
run:<stop reason>
```

错误归一化会：

- 提取 `[NON_ZERO_EXIT]` 这类显式错误码；
- 把变化的数字替换为 `#`；
- 把长随机 ID 替换为 `<id>`；
- 每个 Cluster 最多保留 3 个示例。

这种方案不如向量语义聚类灵活，但对于当前项目规模更可解释、可测试，也不会因为聚类模型变化导致历史 Dashboard 抖动。以后数据量足够时，可以在确定性签名之上增加二级向量聚类，而不是替换一级签名。

## 11. Dashboard 与回归告警

```powershell
python -m MiniClaw.trace.cli report `
  D:\MIniClaw\.aster `
  --out D:\MIniClaw\.aster\dashboard
```

输出：

```text
summary.json    机器读取、CI 基线
report.md       代码评审和归档
dashboard.html  本地直接打开
```

指标包括：

- Run 成功率、失败率；
- Eval pass rate 和置信等级来源；
- 唯一 Goal 完成率；
- 总 Token、平均 Token；
- 总成本、平均成本；
- 平均延迟、p95 延迟；
- 按 Provider/Model 拆分的请求、错误、Token、成本、延迟和 purpose；
- 按 Tool 拆分的调用、错误率和延迟；
- 审批数量；
- Compaction 尝试、完成、延迟、失败、策略和节省 Token；
- 失败 Cluster。

与旧基线比较：

```powershell
python -m MiniClaw.trace.cli report `
  D:\new-traces `
  --out D:\new-dashboard `
  --baseline D:\baseline-dashboard\summary.json
```

默认告警线：

| 指标 | 触发条件 |
| --- | --- |
| Failure rate | 上升至少 5 个百分点 |
| Eval pass rate | 下降至少 5 个百分点 |
| Goal completion | 下降至少 5 个百分点 |
| p95 latency | 上升至少 20% |
| Average cost | 上升至少 20% |
| Tool error rate | 上升至少 5 个百分点 |

## 12. 模块边界

```text
src/MiniClaw/trace/
├─ store.py        TraceRecorder、脱敏、Token/成本归一化
├─ model_client.py 全部模型请求的统一包装器
├─ analysis.py     分组、迁移、Eval Case、聚类、Dashboard、告警
├─ replay.py       无真实 Tool execution 的模型边界重放
└─ cli.py          migrate / eval-case / replay / report
```

依赖原则：

- `TraceRecorder` 只观察，不改变模型回复或 Tool Result；
- Trace 写失败不能让用户任务失败；
- `AgentLoop` 不读写 Trace 文件；
- Replay 不调用 ToolExecutor；
- Dashboard 不调用生产模型；
- 成本没有价格配置时保持 0；
- Eval 的置信范围必须显式标明。

## 13. 完整使用流程

```text
1. 用户通过飞书或 CLI 执行真实任务
2. Session 自动产生 trace.jsonl
3. Dashboard 找到高频失败 Cluster
4. 对具体失败运行 eval-case
5. 准备模型、Prompt 或 Tool 配置变体
6. 使用 replay 安全比较每个模型决策边界
7. 结果追加到 eval-results.jsonl
8. 重新生成 Dashboard，与 baseline 比较
9. 对通过边界回归的候选方案再运行隔离工作区集成测试
10. 上线后新的真实 Trace 验证回归是否真的消失
```

这就是 Trace → Eval 的数据闭环：生产失败不再只是一段聊天记录，而会变成可迁移、可重放、可聚类、可回归比较的数据资产。
