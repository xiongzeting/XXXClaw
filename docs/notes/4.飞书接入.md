# MiniClaw 飞书接入

MiniClaw 的飞书接入参考 pi-mono Mom 的产品行为，但没有导入或调用 pi-mono 的 Agent 实现。

## 边界

```text
飞书官方 SDK 长连接
        ↓
FeishuBot：事件规范化、群聊 @ 与线程判断
        ↓
FeishuAssistantRouter：去重、每会话队列、Session 隔离
        ↓
CodingAssistant
        ↓
AgentLoop → MiniClaw llm → 模型 API
```

初次迁移时复用了 pi-mono `.env` 中所需的配置值，但 MiniClaw 运行时只接受自己的变量名：

```dotenv
MINICLAW_FEISHU_APP_ID
MINICLAW_FEISHU_APP_SECRET
MINICLAW_FEISHU_SESSION_SCOPE
MINICLAW_PROVIDER
MINICLAW_PRIMARY_API_KEY
MINICLAW_PRIMARY_BASE_URL
MINICLAW_PRIMARY_MODEL
MINICLAW_CONTEXT_WINDOW
MINICLAW_MAX_OUTPUT_TOKENS
```

这些值保存在被 `.gitignore` 排除的本地 `D:\MIniClaw\.env` 中，不会写入源码、文档、测试或日志。CLI 和飞书默认读取当前目录 `.env`，也可通过 `--env-file` 指定其他 MiniClaw 配置文件；同名系统环境变量优先。

## 消息规则

- 私聊消息直接处理；
- 群聊需要 @ 机器人；
- 已由 MiniClaw 管理的线程可以不重复 @；
- 同一 conversation 最多排队 5 条消息；
- message ID 同时做内存和 JSONL 去重；
- `thread`、`channel`、`user` 三种 Session Scope 与 pi 的构造语义一致；
- 处理开始时回复“MiniClaw 正在处理…”，完成后编辑为最终结果；
- 超过飞书单条限制的回答自动分片。

## Session 位置

```text
.aster/feishu/events.jsonl
.aster/feishu/sessions/<session-key>/context.jsonl
```

每个飞书线程使用独立 Working Context，但继续共享当前项目的 Semantic Memory 和 Skill 目录。

## 启动

```powershell
$env:PYTHONPATH = "D:\MIniClaw\src"
python -m MiniClaw.platforms.feishu.cli `
  --workspace D:\MIniClaw
```

也可以使用启动脚本：

```powershell
pwsh -File scripts/launch/start-miniclaw-feishu.ps1 `
  -Workspace D:\MIniClaw
```

飞书应用需要启用机器人能力，选择长连接事件订阅，并订阅 `im.message.receive_v1`。发送消息和编辑消息需要对应的 IM 权限。
