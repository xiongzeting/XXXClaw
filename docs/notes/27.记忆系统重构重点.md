# MiniClaw 记忆系统重构重点

## 结论

本轮重点不是继续增加检索算法，而是把“真实写入、原文证据、动态召回、跨会话恢复、Benchmark”统一成同一条生产链路。

当前主流程：

```text
任务运行
  ├─ 当前消息继续保存在 Working Context
  ├─ 压缩时完整历史进入 Archive
  └─ 任务结束生成 Episode
          ↓
只有任务真正完成
          ↓
模型保守提炼稳定事实和 Procedure Candidate
          ↓
Evidence Ledger 保存来源、Session、用户/频道范围和置信度

新请求到达
  ↓
Semantic / Episode / Archive / Skill 分别混合召回
  ↓
Episode 命中后自动二跳到对应历史 Session 的 Archive
  ↓
跨来源 RRF + Cross-Encoder 重排
  ↓
状态、置信度与“当前/最新”查询的时效重排
  ↓
最多选择 12 条证据并共享 15k Token 预算
  ↓
以“不可信历史证据”的 user 消息注入，永不进入 system
  ↓
工具发现新错误码、路径或实体时，最多动态刷新 3 次
```

## 本轮完成的关键修改

### 1. 写入链路与真实 Assistant 对齐

- 新增 Evidence Ledger，记录每条长期事实或任务摘要来自哪个 Session、文件、用户和频道。
- `memory remember/replace/conflict_resolve` 的主动工具写入也进入同一 Evidence Ledger；显式工具来源优先于后续模型对同一事实的重复提炼来源。
- 短任务中的显式 `remember` 指令不再依赖触发压缩，任务结束时也会确定性写入。
- 只有状态为 `completed` 的任务才调用模型提炼稳定事实；Goal 仍为 `active/verifying/waiting_for_user` 时只保存活动 Episode，不污染长期事实。
- 模型生成的 Procedure 先写为候选，不自动升级成 Skill。
- 一次 debug、benchmark 的样本数、通过率、延迟和 Token 等指标统一拒绝写入 Semantic。
- 新事实与旧事实冲突时默认保留旧值；冲突提议只作为非活动审计证据保存。

### 2. Archive 从孤立文本升级为 ActionBlock

旧结构的父节点通常只是一条消息。现在会把以下内容绑定到同一个逻辑块：

```text
Assistant Tool Call
  → 对应 Tool Result
  → 后续判断或验证结论
```

检索仍先在小块上找精确命中；命中后返回完整操作上下文。大工具 Artifact 不会整份强塞进 Prompt，而是返回工具调用/结果引用/判断，加上命中原文附近的证据块。

旧版 `archive-index.jsonl` 没有 ActionBlock 字段时仍可正常读取。

### 3. 召回不再只发生在任务开头

- 第一次模型请求前执行初始召回。
- Read、Grep、Bash 等工具暴露新的错误码、文件名、路径或关键实体后，重新组合“原请求 + 新工具证据”检索。
- 单次任务最多动态刷新 3 次，避免每个 Tool Call 都重复搜索。
- 没有任何可检索记忆时跳过动态刷新。
- 每次刷新原因、查询、命中数量和注入内容写入 Trace。

### 4. 跨会话原文自动二跳

过去自动 Archive 搜索只查当前 Session。现在先检索 Episode；如果命中过去的任务，再自动进入该 Episode 对应的历史 Session 搜索 Archive 原文。

因此模型不需要先看见 Episode，再自己决定调用 `memory archive_search` 才能拿到历史证据。主动 Memory Tool 仍保留，作为多跳不足时的深挖手段。

### 5. 检索索引持久化

新增 SQLite 检索缓存：

- 文档 Token 数和 BM25 倒排表持久化。
- Dense 向量与 FAISS HNSW 索引持久化，模型、维度或索引参数变化时自动建立独立索引。
- 路径、文件名、错误码、类名、函数名走独立精确召回通道，再与 BM25、Dense 通过 RRF 融合。
- 默认本地模型升级为 `BAAI/bge-m3` 与 `BAAI/bge-reranker-v2-m3`；模型或 FAISS 不可用时明确回退，不在运行时联网下载。
- 本地 Bi-Encoder 的文档与查询向量持久化。
- 重启后相同文档不再重复分词和编码。
- 当前文档作用域完整进入 ANN 后，后续不同查询只编码/读取 Query，直接搜索持久化 FAISS，不再加载全量文档向量。
- Archive 与 Evidence Ledger JSONL 都按文件大小与修改时间缓存解析结果，同一轮多来源召回不会反复读取并解析整份历史或证据账本。
- 缓存超过阈值后保留最近 10 万条，避免无限增长。
- 本地模型不存在时仍回退 LocalHash，不会运行时联网下载。

### 6. 排序、预算与可信边界

- Episode 的 `completed/resolved` 会优先于同相关性的 `failed/cancelled`；低置信度候选会被降权。
- 查询包含“当前、最新、最近、now、latest”等时，记录时间参与最终重排。
- Prompt 不再按排名从头顺序截断；最多 12 条候选先做来源多样性选择，每条获得最低额度，再轮转分配剩余 Token，避免首个超长 Archive 吞掉全部预算。
- `retrieval_trace()` 只返回模型实际看到的条目与截断后正文；预算前候选由 `ranked_retrieval_trace()` 单独记录。
- 召回历史被包装为明确的“不可信证据”并放在 user role。记忆中的指令、角色声明或工具请求不能升级为系统策略。
- 动态刷新会把新旧候选合并后重新排序，旧的高分证据不会被一批低分新结果直接挤掉。

### 7. 飞书记忆作用域

飞书创建 Assistant 时传入用户和频道标识，记忆目录按作用域哈希隔离。Evidence Ledger 同时保留用户、频道、工作区和 Session 来源，避免不同飞书会话直接共享同一份长期记忆文件。

### 8. Benchmark 不再生成特供记忆

ContextWeave 旧适配器曾用规则扫描稳定句和流程句，并直接生成 Semantic、Procedural。该逻辑已删除。

新版适配器：

- 每条历史记录使用真实 `session_id`。
- 使用生产版任务结束整理生成 Episode。
- 只接受生产规则允许的显式稳定事实。
- Skill 只来自真实 Skill 目录。
- 召回直接调用 `MemoryManager.prompt_context()`。

因此旧版 6 题对照成绩需要重新跑，不能与新版混写。

## 验证重点

- 当前全量 `unittest`：**268/268 通过**。
- 当前正式端到端记忆 Eval：跨会话记忆、多跳事实、偏好召回 **3/3 通过**；7 次真实运行中无模型错误、无工具错误。
- 覆盖持久化索引重启复用、ANN 稳态仅查询向量、失效文档重新激活、ActionBlock、Archive 解析缓存、旧 Archive 兼容、动态召回合并、Episode→Archive 二跳、保守事实写入、冲突处理和飞书作用域。
- Trace 回归测试同时校验“预算前候选”和“模型实际可见证据”，避免 `injected_count` 再次虚高。
- ContextWeave 生产链路烟雾题证明链路可运行，但不能代替重跑后的正式 held-out 正确率；新旧实现成绩不得混写。

## 面试时最重要的一句话

> 我没有把 Memory 只做成一个向量库，而是把它拆成“可恢复原文、任务级摘要、稳定事实和操作规则”四种生命周期；写入时保守并保存证据，读取时先分来源召回，再跨来源融合，并允许工具发现新实体后在任务中动态刷新。
