# BGE 与持久化检索升级

## 最终检索流程

```text
用户问题
  ├─ 精确符号通道：路径、文件名、错误码、类名、函数名
  ├─ BM25 通道：SQLite 持久化倒排索引
  └─ Dense 通道：BAAI/bge-m3 → SQLite 向量缓存 → FAISS HNSW
                         ↓
                  加权 RRF 候选融合
                         ↓
              BAAI/bge-reranker-v2-m3
                         ↓
                  最终相关记忆证据
```

## 这次真正替换了什么

- Bi-Encoder 默认模型改为 `BAAI/bge-m3`，输出进行 L2 归一化。
- Reranker 默认模型改为 `BAAI/bge-reranker-v2-m3`。
- BM25 不在每次查询时重新构建语料索引：文档长度、词频和倒排表保存在 `retrieval-cache.sqlite3`。
- Dense 不再对全部文档逐一计算余弦：向量保存在 SQLite，近邻索引保存在 `retrieval-cache.sqlite3.ann/*.faiss`。
- 首次搜索批量编码 Query 与文档并同步索引；作用域已完整索引后，后续搜索只处理新 Query，直接走持久化 ANN。
- 增加代码精确召回。路径、错误码和代码符号不会只依赖分词或语义相似度。

## 持久化与失效规则

向量索引由以下信息共同确定：

```text
向量后端 + 模型名 + 设备 + Query/Document 前缀
+ 向量维度 + HNSW M 参数
```

模型、维度或 HNSW 参数变化会使用新的索引标识，不会误读旧向量。新文档增量写入 SQLite 和 FAISS；缓存淘汰的文档先标记失效，索引在发现数量不一致时重建。

如果先前失效的文档重新进入当前作用域，会恢复原标签和已保存向量，并重新加入 FAISS，而不是因唯一键冲突永久退回线性检索。缓存命中同时刷新最近使用时间；淘汰时当前调用中的文档属于受保护集合。

每次搜索仍以调用方传入的文档列表作为硬边界。即使同一 FAISS 文件中包含多个用户、频道或 Session 的向量，也只允许返回当前范围中的文档；搜索深度不足时会逐步扩大，而不是放宽隔离条件。

## 回退策略

- 本地没有 BGE 模型：回退到无依赖的 LocalHash 向量，不联网下载。
- 没有 FAISS 或索引损坏：回退到 SQLite 向量缓存加线性余弦。
- Reranker 不可用：保留精确搜索、BM25、Dense、RRF 与确定性重排结果。
- 任一回退都会写入检索诊断字段，便于 Trace 和 Benchmark 区分“模型效果差”与“后端没有真正启用”。

## 配置

```ini
MINICLAW_MEMORY_VECTOR_ENABLED=true
MINICLAW_MEMORY_VECTOR_MODEL=BAAI/bge-m3
MINICLAW_MEMORY_VECTOR_DEVICE=auto
MINICLAW_MEMORY_VECTOR_BATCH_SIZE=8
MINICLAW_MEMORY_VECTOR_QUERY_PREFIX=
MINICLAW_MEMORY_VECTOR_DOCUMENT_PREFIX=

MINICLAW_MEMORY_ANN_ENABLED=true
MINICLAW_MEMORY_ANN_HNSW_M=32
MINICLAW_MEMORY_ANN_EF_SEARCH=96
MINICLAW_MEMORY_EXACT_WEIGHT=0.36

MINICLAW_MEMORY_CROSS_ENCODER_ENABLED=true
MINICLAW_MEMORY_CROSS_ENCODER_MODEL=BAAI/bge-reranker-v2-m3
MINICLAW_MEMORY_CROSS_ENCODER_DEVICE=auto
MINICLAW_MEMORY_CROSS_ENCODER_BATCH_SIZE=4
```

BGE-M3 默认不强制增加 Query 指令，因此前缀保持为空；配置项保留给后续模型切换和对照实验。

## 验证重点

- 重启后复用文档与查询向量，不重复编码。
- FAISS HNSW 重启后继续读取磁盘索引。
- 模型或维度变化时使用新索引。
- ANN 只返回当前调用允许的文档。
- 第二个不同 Query 只编码 Query，诊断显示 `ann_vector_source=persistent-index`。
- 被淘汰标记失效的文档再次出现时能够重新激活。
- FAISS 缺失时线性检索仍能工作。
- 路径、错误码、类名和函数名能够精确命中。
- 普通自然语言问题不会被无关代码符号强行压过。
