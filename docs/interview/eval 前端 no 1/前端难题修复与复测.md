# 前端难题：修复与原题复测

本次根据《前端新难题实测报告》修改 Agent 与真实前端，然后重跑原来的三道开发题。原始成绩与现场记录保留，后台的另一轮难题不受本次修改影响。

## 已修改

| 优先级 | 原来 | 现在 | 为什么 |
|---|---|---|---|
| P0 验收条目 | 用整句描述作键，换个说法就多一条旧要求 | 固定编号、描述、版本分开；措辞修改复用编号，要求变化升版本，撤销单独留记录 | 避免为了同一要求反复验证；改变要求后也不能沿用旧证明 |
| P0 验证证据 | stdout/stderr 混在一起解析；任意命令都清空验证 | 单独解析 stdout 的逐项 JSON，严格校验版本、布尔值、证据和退出码；比较文件变化及覆盖制品哈希决定失效 | 正常日志不再破坏验收，只读检查不再白费；无法确认的副作用仍保守处理 |
| P0 收尾与页面 | 没有 Goal 仍提供完成工具；暂停页显示完成 | 无显式 Goal 时隐藏 `goal_complete`；暂停按真实待办生成下一步；SSE 传递真实终态，页面显示暂停并提供恢复入口 | 任务完成、执行暂停和连接结束分别表达，页面与 Trace 对齐 |
| P1 重复上下文 | 保存的代码和大输出反复发给模型 | 已闭合工具调用的大内容在请求副本中换成简短预览与可回读制品；原始调用不改，失败信息保留 | 降低重复输入，同时留住审计依据和按需恢复能力 |
| P1 整理记忆 | 每轮结束又整理整段会话 | 记录已处理位置和摘要，重启后恢复；处理新增证据，没有新增工作证据时保留摘要并跳过模型整理 | 普通对话收尾不应重新付一次全量整理费用；明确记忆请求继续处理 |
| P1 环境信息 | 强制读未安装的 skill，仅凭 PATH 判断浏览器不存在 | 工具说明与 skill 目录一致；启动时探测实际 Edge、Python/Node Playwright 路径，区分宿主和容器 | 减少寻找不存在工具，以及错误宣称无法验证 |

验收脚本与清单仍可能被模型写错，这些机制不能代替独立业务检查。文件前后快照用于验证证明是否过期，不宣称捕获任意 Host shell 的所有瞬时副作用。记忆历史前缀发生改变时会保守重新处理，尚未验证所有压缩和恢复组合的成本。

## 复测规则

- 同模型 `primary / gpt-5.6-luna`，同 Host/direct，通过真实无头 Edge 操作产品页面。
- 三方 JSON 合并、约束路径规划、导入撤销看板；每题原有三阶段，共 9 次前端请求。
- 原题、输入资料、业务验收脚本不变。每题仍为 **180,000 tokens、45 次工具调用、900 秒**；每次执行仍最多 **32 步**。
- 新工作区 `agent-hard-ui-fixed-20260906`，没有复制旧实现。标准答案和独立验收放在工作区外，不把评分反馈给实现中的模型。
- 新版评分适配器同时核对 SSE 结束态、Trace 和页面；这是观察口径补齐，业务标准未改。

## 验证与结果

修复后的 **96 项离线回归通过**；真实无头 Edge 加脚本化事件的四种终态、待办显示和恢复按钮检查通过。离线检查不计入模型任务成绩。

### 阶段结果（2026-09-06，已完成 7/9 次请求）

合并、路径两题已跑完，看板完成第一阶段，第二阶段仍在执行。以下不是三题最终成绩。

两道完整任务合计 token **增加 1.05%**，严格整题通过 **0/2**，因此目前不能说成本优化已整体见效。两题第三阶段均按要求只回复指定短句、零工具调用，而且没有再次调用模型整理记忆；这项行为已生效，但短回复仍携带历史上下文。

页面、SSE 和 Trace 的已完成阶段终态一致；冻结源码及验收脚本没有变化。合并记录 1 次请求重试，路径记录 3 次请求重试和 1 次模型错误，但最终均恢复并交付，**可用性均按通过处理**。表中耗时是页面实际等待时间，包含重试等待，不把这部分直接解释为能力退步；token 为现有 Trace 的累计用量，不能据此精确拆出供应商未返回用量的失败请求成本。

### 目前仍需优先修改

1. **P1：验证脚本卡住后尽快定位，避免原样重试。** 看板第一阶段有 4 次命令超时，设置的超时分别为 120、300、120、20 秒；最终功能检查仍是 8/8。应为浏览器验证加分步日志、单步超时和可靠退出/资源关闭，在连续同类超时后先诊断；不能仅延长等待。当前只能确认脚本未及时退出，尚不能确定每次卡住的具体根因。
2. **P1：继续减少重复历史输入。** 合并题第二阶段的输入来源估算中，工具结果约 165,627 tokens、工具参数约 114,488 tokens。大内容落盘和增量整理已经改动，但仍不能覆盖所有重复输入成本；需核对每次请求实际保留了哪些已完成代码与日志，按证据调整。来源数是本地估算，不与供应商用量混作精确分账，也不能把全部耗费归为记忆召回。
3. **P2：环境信息需压过旧经验，自写测试要核对规则。** 看板仍尝试读取未安装的 `powershell-safe-invocation`，合并和看板仍在非 Git 目录执行 Git 状态检查；合并自写测试也出现错误预期后反复修改。继续明确当前可用能力，并用公开规则推导关键预期，减少无效试探。独立业务验收保留，不能仅凭模型自写测试通过就宣称完成。

当前安全通过仅覆盖已有输入保护、工具写入路径及源码冻结检查，不代表所有任意 shell 瞬时副作用均已验收。最终三题对比待看板后两阶段完成后补齐。
