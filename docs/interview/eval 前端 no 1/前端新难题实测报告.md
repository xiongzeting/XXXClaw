## 先修什么：按优先级

### P0：修验收与任务完成协议，先消除收尾循环

**证据：**看板功能已通过浏览器检查，Agent 却在首轮用了 40 次工具调用、32 次模型请求，最终因步数上限暂停。其中 5 次调用 `goal_complete`，反复修改验证脚本仍未顺利收尾。暂停回复还同时出现“尚未确认完成”和“下一步：无，已完成”的矛盾内容。

**根因与修改方向：**

- 现在用整段验收描述作为匹配键，同一要求的空格或措辞变化会产生新条目，旧条目仍待验证。改成**稳定的 criterion_id + 可更新描述 + 明确版本**；新增、修改、撤销要求分别处理，不能不断追加近似重复项。
- 命令工具合并 stdout/stderr，验收器却把整段输出当纯 JSON 解析。改成**验证数据与诊断日志分开返回**，继续严格检查退出码、布尔类型和证据，不靠屏蔽错误日志才能通过。
- 当前任何 bash 都会清空已有验证，包括只读查询。应依据验证覆盖的文件/制品版本及可确认的修改来失效；无法确认是否有副作用的命令仍保守处理，不能简单放宽。
- `TaskProgress` 与可选 Goal 的完成入口要区分清楚；没有 Goal 时不应引导模型反复调用 `goal_complete`。暂停时必须依据真实待办生成可执行下一步，不能照搬模型的“已经完成”。

**复测标准：**用不同措辞、正常诊断日志、只读查询、实际文件修改组成通用分布：该保留的验证能保留，该失效的必须失效；有待验收项不能完成，全部完成后也不能卡在自写脚本循环。保留现有步数上限。

### P0：前端必须展示真实运行状态，评分不能只看流结束

**证据：**看板首轮 Trace 明确为 `status=paused, stop_reason=budget_exhausted`，前端状态栏却显示“已完成”。SSE `done` 只说明传输结束。

**修改方向：**结束事件携带并展示 success / paused / cancelled / error；暂停提供真实待办与恢复入口。验收器同时核对页面状态、结束事件和 Trace，不能将 HTTP/SSE 正常结束等同于任务成功。

这轮已修正**本次评分适配器**的观察口径，未修改前端产品：原 UI-only 评分另存，复核增加真实运行状态检查。看板的可靠性从“误判通过”改为“未通过”，本批可靠性汇总因此为 **2/3**；全维通过仍为 **0/3**。这是评分纠错。题目、预算和业务验收没有更改，也没有模型重跑。

### P1：减少重复发送的工具历史，并按增量决定是否整理记忆

**证据：**全批约 **307.4 万 tokens**，没有一次压缩。看板第二轮主模型累计输入的估算来源中，工具结果约 **52.4 万**、工具参数约 **40.0 万**，重复工具内容是明显大头。仅最后一句“看板会话正常”也用了 **75,485 tokens**，其中记忆整理 **11,329**。

**修改方向：**在调用已闭合、文件已保存并可回读时，逐步用制品引用替代重复的大段代码参数和工具输出，不必等上下文快塞满才处理；保留关键约束、失败信息和调用配对。记忆整理依据本轮新增可沉淀证据和已处理位置决定，避免没有新增工作证据时仍重新整理整段历史。这是通用生命周期策略，不给“只回复某句话”写专用捷径。

**复测标准：**固定结果验收和预算，对照主模型输入、工具参数/结果体积、辅助整理成本和调用次数；省下的内容必须能按需恢复。先消除 P0 收尾循环，再评价剩余的上下文成本。

### P1：工具说明与实际可用能力对齐

**证据：**合并和路径两题都尝试读取不存在的 `powershell-safe-invocation`；新工作区未安装该 skill，但 Bash 工具说明仍要求先读它。看板最终声称环境没有 Edge/Playwright，而本轮独立验收实际正通过已安装的 Edge 与 Playwright 运行；它的 PATH/局部模块探测不足以支持“整个环境不存在”的结论。

**修改方向：**启动时从真实注册表与环境探测结果生成能力信息，核对 skill 是否挂载、工具是否满足当前状态、浏览器验证能力是否可用。区分“不在 PATH”“当前工具无法访问”“确实不存在”，不能靠追加更强硬的 prompt 解决。
